3) Saliency logic (sales-weighted)

We need a computed field: attentionScore per SKU for the selected Store (and selected Client if client filter is applied).

3.1 Scope (what rows to use)

Use the current Store selection context already used on Store Overview.

Use current week ending (same week the tasks page uses).

For sales weighting, use Sell Out (P4 weeks) from the current week row (or latest available week for that barcode in that store).

3.2 Action priority weights (baseScore)

Use Action Column text to classify into these buckets:

Highest to lowest base priority:

Fix Counts: Negative SOH → baseScore 100

Urgent: DC OOS → baseScore 90

Urgent: Place Order - DC has stock → baseScore 85

OOS – Stock on Order → baseScore 80

Review: Risk of OOS → baseScore 70

Check Count: No Sales in 30 Days → baseScore 50

Monitor: Possible Overstock → baseScore 40

Optimal → baseScore 10 (keep eligible but will rarely rank)

Match by startsWith / includes string matching on Action Column.

3.3 Sales impact modifier (salesScore)

Compute salesScore using Sell out p4 weeks for the store:

Calculate the store median of Sell out p4 weeks across all SKUs for the current week.

Calculate store 75th percentile (top 25%) for the current week.

SalesScore rules:

If Sell out p4 weeks >= 75th percentile → +30

Else if Sell out p4 weeks > median → +15

Else → +0

3.4 Stock risk modifier (riskScore)

If Store SOH == 0 → +20

If Store SOH < 0 → +25 (negative is extremely important)

If WFC <= 1 → +15

If WFC between 1 and 2 → +8

Else → +0

3.5 Final score and selection

attentionScore = baseScore + salesScore + riskScore

Then:

Filter to SKUs in the current Store & current week

Sort descending by attentionScore

Return top 5 unique barcodes

IMPORTANT: if multiple rows exist for the same barcode across weeks, use latest week only (current week).

4) Respect client filter + article filter
